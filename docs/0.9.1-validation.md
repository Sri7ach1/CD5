## Automated checks

Run `./scripts/test.sh` for host tests, or `sudo ./scripts/test.sh --sdk` to
include HTTP fault injection against the SDK curl headers. The suite covers:

- READ CD failure -> STOP, retry from track start, pause/resume and navigation.
- AudioOut failure propagation and process failure from STOP.
- Optical INQUIRY selection, descriptor cleanup, missing/reconnected devices,
  scan limits and bounded read retries (with mocked CAM responses).
- Concurrent metadata/TOC publication and clear over 20,000 updates.
- TOC bounds, audio/data tracks, CD-Extra sessions, malformed/truncated input.
- Disc ID SHA-1/base64 and first/last-track query numbering.
- Missing/invalid metadata and rejection of mismatched medium track counts.
- Cover decode, dimension limits, fallback and absent/error distinction.
- Manifest rejection of incomplete builds, changed inputs and package tampering.
- HTTP retry limits, HTTPS-only redirects, certificate verification options,
  response size cap, 404/429 behavior and response ownership.

Extracted production functions are compiled with host mocks where the complete
translation unit requires PS5/CAM headers. These tests do not validate platform
ABI or physical device behavior. The complete application is separately built
with the PS5 SDK. A previous first-increment binary is not evidence for the
current candidate: use its new SHA256 and build manifest.

## Policies to validate on PS5

- Readers: enumerate /dev/pass* with at most 16 candidates per scan; reject
  non-optical INQUIRY responses; prefer an optical reader reporting audio.
  An optional CD5_DEVICE environment value pins a /dev/passN path if the loader
  can supply environment variables. Without a pin, selection among multiple
  ready audio readers follows directory enumeration order.
- Waiting: the UI is active; scans repeat with a one-second delay. Square closes
  CD5 while waiting or showing an unsupported disc. Individual CAM commands
  still block the player thread up to their timeout; drawing runs separately.
- Reading: request CD-DA sectors only. At most three attempts for CAM busy,
  EINTR/EAGAIN or aborted command; no retry of UNIT ATTENTION or missing medium.
  No synthetic replacement sectors. A permanent read error with ready medium
  enters STOP. X retries the selected track from its beginning.
- AudioOut: unrecoverable output/init errors notify and exit. Relaunch is required;
  reopening AudioOut within the process is not implemented.
- TOC: format 0 is checked against raw format 2 session descriptors. Mixed discs
  require a valid full TOC. Session A2 bounds audio; no fixed-sector adjustment.
  Unsupported/contradictory TOCs show an error, with X/OPTIONS to retry.
- Metadata: snapshots protect UI metadata/track lists. A second readiness/TOC
  check rejects results if the medium changed while HTTP was running. Identical
  TOCs are treated as the same disc; this is not a physical-disc serial number.
- Network: two attempts maximum for selected transient failures; no automatic
  404, 429 or certificate-error retry. OPTIONS reloads disc information and
  restarts playback from track 1. Requests remain synchronous during disc load:
  input can wait for the bounded HTTP timeout (up to 30 seconds per attempt).
- Lyrics retain their mutex and generation check. No persistent cache is added.

## TOC policy references

The T10 MMC-5 draft, sections 6.20.2.2 and 6.25.3.4, defines the CD-DA expected
sector type and raw TOC session descriptors used here:
https://www.13thmonkey.org/documentation/SCSI/mmc5r02c.pdf
The parser checks the session A2 lead-out against the track bounds and the final
basic TOC lead-out. This supplies the actual audio boundary instead of guessing
a fixed gap before a data session. Inconsistent responses are rejected.
